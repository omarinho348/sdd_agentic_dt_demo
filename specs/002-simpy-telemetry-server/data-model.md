# Data Model: SimPy Simulation Engine & Web Telemetry Server

## AssemblyLineConfig

Validated runtime configuration derived from `assembly_line.json`.

| Field | Type | Validation |
|---|---|---|
| `station1_cycle_time` | float | Greater than 0; read from Station1 `cycle_time` description/value contract |
| `station2_cycle_time` | float | Greater than 0; read from Station2 `cycle_time` description/value contract |
| `queue_capacity` | int | Greater than 0; read from Queue `capacity` description/value contract |
| `item_interval` | float | Fixed at 2.0 simulated seconds for this feature |

The DTDL generated by Feature 001 carries configured numeric values in content descriptions. The ingestion adapter must validate and parse those values from the contract representation without introducing a second configuration file.

## TelemetryFrame

Pydantic model serialized for WebSocket clients.

| Field | Type | Validation |
|---|---|---|
| `timestamp` | float | Non-negative SimPy time |
| `station1_state` | literal | `IDLE`, `BUSY`, or `BLOCKED` |
| `station2_state` | literal | `IDLE`, `BUSY`, or `BLOCKED` |
| `queue_occupancy` | int | Greater than or equal to 0 and less than or equal to configured capacity |

The model serializes to the exact JSON keys in the WebSocket contract. No additional fabricated state is required.

## SimulationState

Internal simulation-owned state:

- Station 1 state
- Station 2 state
- Current queue occupancy
- Current SimPy timestamp
- Item sequence number

Only the simulation thread mutates this state. It publishes immutable `TelemetryFrame` snapshots to the thread-safe event queue.

## ConnectionManager

Async server-owned collection of active WebSocket connections.

- `connect`: accept and register a client.
- `disconnect`: remove a closed client without stopping simulation.
- `broadcast`: send one serialized frame to all current clients and remove failed connections.

## State transitions

1. Station starts `IDLE`.
2. Item enters Station 1: Station 1 becomes `BUSY`.
3. Station 1 completes while Store is full: Station 1 becomes `BLOCKED` until capacity is available.
4. Station 1 places an item in the Store: occupancy increments and Station 1 returns to `IDLE` or begins the next item.
5. Station 2 retrieves an item: Station 2 becomes `BUSY`.
6. Station 2 completes: Station 2 returns to `IDLE`.
7. Every transition or occupancy change publishes a validated frame.
